# 快速开始

本文帮助你在最短时间内**启动 GustoBot**、做一次**检索与对话**联调，并熟悉常用命令。完整部署与端口说明见 [部署指南.md](部署指南.md)；环境变量见 [环境变量与配置说明.md](环境变量与配置说明.md)；代码结构见 [项目架构.md](项目架构.md)。

---

## 1. 启动前准备

1. 克隆仓库并进入根目录。  
2. 复制环境变量模板并填写 **LLM**、**Embedding**（及可选 Rerank、Milvus、Neo4j 等）：

   ```bash
   cp .env.example .env
   ```

3. 推荐使用 **Docker Compose V2**（命令为 `docker compose`；若你仍使用旧版，可将下文命令改为 `docker-compose`）。

---

## 2. 一键启动（Docker）

在仓库根目录：

```bash
docker compose up -d --build
```

常用命令：

```bash
docker compose ps
docker compose logs -f backend
```

### 2.1 默认端口（与 `docker-compose.yml` 一致）

| 服务 | 地址 |
|------|------|
| FastAPI / OpenAPI | http://localhost:8000 、 http://localhost:8000/docs |
| 健康检查 | http://localhost:8000/health |
| Neo4j Browser | http://localhost:17474 |
| MySQL | `localhost:13306` |
| Redis | `localhost:6379` |
| Milvus | `localhost:19530` |
| pgvector（kb_postgres） | 默认 `localhost:5433`（可用 `KB_PG_PORT` 覆盖） |
| kb_ingest | 默认 `localhost:8100`（可用 `KB_INGEST_PORT` 覆盖） |

根路径 `/` 会重定向到 `/docs`；聊天 Web 界面在仓库 **`web/`** 目录，本地开发可执行 `npm run dev`（见 `scripts/start_chatbot.py` 一键前后端）。

## 3. 仅后端（本地 Python）

```bash
python -m venv venv
# Windows: venv\Scripts\activate
# Linux/macOS: source venv/bin/activate
pip install -r requirements.txt
```

```bash
python -m uvicorn gustobot.main:application --reload --host 0.0.0.0 --port 8000
```

或前后端一起：

```bash
python scripts/start_chatbot.py
```

需保证 `.env` 中的 **Milvus / Neo4j / Redis / MySQL** 等地址指向已启动的服务。

---

## 4. 快速验证

### 4.1 配置是否加载

```bash
python -c "from gustobot.config.settings import settings; print(settings.LLM_MODEL, settings.EMBEDDING_MODEL)"
```

### 4.2 知识库向量检索

`POST /api/v1/knowledge/search` 的请求体为 `query`、`top_k`；响应为 **`results`** 与 **`count`**（不是 `total`）。

```bash
curl -s -X POST "http://localhost:8000/api/v1/knowledge/search" ^
  -H "Content-Type: application/json" ^
  -d "{\"query\": \"红烧肉怎么做？\", \"top_k\": 5}"
```

（Linux/macOS 将 `^` 改为 `\` 或单行执行。）

### 4.3 统一对话

```bash
curl -s -X POST "http://localhost:8000/api/v1/chat/" ^
  -H "Content-Type: application/json" ^
  -d "{\"message\": \"红烧肉怎么做？\", \"session_id\": \"demo-1\", \"stream\": false}"
```

响应中含 `route`、`route_logic`、`sources` 等；具体字段以 `ChatResponse` 为准。

### 4.4 LightRAG（可选）

见 [LightRAG服务指南.md](LightRAG服务指南.md)。示例：

```bash
curl -s -X POST "http://localhost:8000/api/v1/lightrag/query" ^
  -H "Content-Type: application/json" ^
  -d "{\"query\": \"川菜有什么特点？\", \"mode\": \"hybrid\", \"top_k\": 10, \"stream\": false}"
```

## 5. 检索链路（概念）

典型「知识库搜索」路径（与配置有关，日志文案以实际版本为准）：

1. 查询文本 → **Embedding**  
2. **Milvus**（及/或 **PostgreSQL pgvector**）召回候选  
3. 若启用 → **Reranker** 重排  
4. 对话场景下再由 **LangGraph** 路由到子图，用 **LLM** 组织答案  

详细路由类型见 [智能体路由速查.md](智能体路由速查.md)。

## 6. 常见操作

### 6.1 添加单条菜谱

```bash
curl -s -X POST "http://localhost:8000/api/v1/knowledge/recipes" ^
  -H "Content-Type: application/json" ^
  -d "{\"name\": \"鱼香肉丝\", \"category\": \"川菜\", \"ingredients\": [\"猪里脊300g\", \"木耳50g\"], \"steps\": [\"切丝\", \"快炒\"]}"
```

### 6.2 批量导入

```bash
python -m gustobot.crawler.cli wikipedia --query "川菜" --import-kb --limit 10
python scripts/import_recipes.py --file data/recipe.json --batch-size 100 --limit 50
```

详见 [爬虫与批量导入指南.md](爬虫与批量导入指南.md)。

### 6.3 清空知识库（危险）

需显式确认参数：

```bash
curl -s -X DELETE "http://localhost:8000/api/v1/knowledge/clear?confirm=true"
```

### 6.4 查看知识库统计

```bash
curl -s "http://localhost:8000/api/v1/knowledge/stats"
```

响应形态为 `{"status": "success", "data": { ... }}`，具体字段由 `KnowledgeService.get_stats()` 决定。

## 7. API 速查（前缀 `/api/v1`）

### 7.1 知识库（`knowledge_router`，前缀 `/knowledge`）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/knowledge/recipes` | 添加单条菜谱 |
| POST | `/knowledge/recipes/batch` | 批量添加 |
| POST | `/knowledge/search` | 向量检索 |
| DELETE | `/knowledge/recipes/{recipe_id}` | 删除 |
| DELETE | `/knowledge/clear?confirm=true` | 清空 |
| GET | `/knowledge/stats` | 统计 |
| GET | `/knowledge/graph` | Neo4j 默认图快照 |
| POST | `/knowledge/graph/qa` | 图谱自然语言问答 |

### 7.2 对话（`v1/chat`，前缀 `/chat`）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/chat/` | 非流式对话 |
| POST | `/chat/stream` 等 | 流式（见 OpenAPI） |
| GET | `/chat/history/{session_id}` | 历史消息 |
| DELETE | `/chat/session/{session_id}` | 清空会话消息 |
| GET | `/chat/routes` | 路由类型说明 |

### 7.3 LightRAG（前缀 `/lightrag`）

见 [LightRAG服务指南.md](LightRAG服务指南.md)。

完整列表以 **http://localhost:8000/docs** 为准。

## 9. 参数调优（摘录）

在 `.env` 中可调整（说明见 [环境变量与配置说明.md](环境变量与配置说明.md)）：

- **召回与重排**：`RERANK_MAX_CANDIDATES`、`RERANK_TOP_N`、`KB_POSTGRES_SIMILARITY_THRESHOLD` 等  
- **Redis 缓存**：`REDIS_CACHE_EXPIRE`、`REDIS_CACHE_THRESHOLD`、`REDIS_CACHE_MAX_SIZE`  
- **会话历史**：`CONVERSATION_HISTORY_TTL`、`CONVERSATION_HISTORY_MAX_MESSAGES`  

修改后需重启后端使进程重新加载环境变量。

## 10. 常见问题

| 问题 | 处理方向 |
|------|----------|
| Embedding / LLM 连接失败 | 检查 `LLM_API_KEY`、`LLM_BASE_URL`、`EMBEDDING_*`；`docker compose logs -f backend` |
| Milvus 连不上 | `docker compose ps milvus`；确认 `MILVUS_HOST`/`PORT` 在容器内为服务名、本机为 `localhost:19530` |
| Rerank 无结果或报错 | 检查 `RERANK_*`；可临时 `RERANK_ENABLED=false` 缩小问题面 |
| 清空知识库 400 | 使用 `DELETE .../clear?confirm=true` |
| 检索返回字段与文档示例不一致 | 以 OpenAPI 与 `SearchResponse` 为准（`count` 非 `total`） |
