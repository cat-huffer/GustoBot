# 开发指南

本文说明如何在本地搭建 **GustoBot 开发环境**：Docker 与纯本地两种路径、前后端启动、常用命令与排错。与「能跑起来」相关的最短路径见 [快速开始.md](快速开始.md)；端口与 Compose 细节见 [部署指南.md](部署指南.md)；环境变量清单见 [环境变量与配置说明.md](环境变量与配置说明.md)；代码分层见 [项目架构.md](项目架构.md)。

---

## 1. 前置条件

| 项目 | 说明 |
|------|------|
| Python | 3.9+（`pyproject.toml`）；Docker 镜像多为 3.10 |
| Node.js | 16+（用于 `web/`） |
| Docker | 可选；全栈依赖服务推荐 Compose |
| Git | 克隆与协作 |

---

## 2. 方式一：Docker Compose（推荐）

在仓库根目录：

```bash
cp .env.example .env
# 编辑 .env：LLM_API_KEY、LLM_BASE_URL、LLM_MODEL 等

docker compose up -d --build
docker compose logs -f backend
```

常用：

```bash
docker compose ps
docker compose down
```

**说明**

- 服务名以 `docker-compose.yml` 为准，后端一般为 **`backend`**（不是 `server` / `gustobot`）。
- 前端 **`web/`** 不在默认 Compose 里，需本机执行 `npm run dev`（或使用 `scripts/start_chatbot.py` 同时拉起前后端）。
- 默认端口摘要见 [部署指南.md](部署指南.md#21-默认端口与-compose-一致)。

---

## 3. 方式二：本地 Python + 前端

### 3.1 后端

```bash
python -m venv venv
# Windows: venv\Scripts\activate
# Linux/macOS: source venv/bin/activate

pip install -r requirements.txt
```

启动任选其一：

```bash
# 与历史文档一致的入口（转调 scripts/run.py）
python run.py start

# 或直接 uvicorn
python -m uvicorn gustobot.main:application --reload --host 0.0.0.0 --port 8000
```

其他子命令（见 `scripts/run.py`）：

- `python run.py start prod` — 多 worker（无 reload）  
- `python run.py test` — 探测 `/health` 与 `/api/v1/chat/`  
- `python run.py check` — 检查 Python 版本与核心依赖  
- `python run.py docker` — 调用 `docker-compose`（若你环境已改为 `docker compose`，可手动执行）

**依赖服务**：若不全栈 Docker，需在本地启动 **Redis、Milvus、Neo4j、MySQL** 等，并把 `.env` 中的 host/port 指到可达地址（本机连 Compose 中的 MySQL 时常用 **`localhost:13306`**，与 Compose 映射一致）。

### 3.2 前后端一起（开发）

```bash
python scripts/start_chatbot.py
```

会在子进程中启动后端 uvicorn 与前端 Vite（详见脚本内逻辑）。

### 3.3 仅前端

```bash
cd web
npm install
npm run dev
```

默认 **http://localhost:5173**；端口可用环境变量 **`VITE_PORT`** 覆盖（见 `web/vite.config.ts`）。

## 4. 环境变量与前端代理

### 4.1 后端 `.env`

从模板复制：

```bash
cp .env.example .env
```

至少配置 **LLM**（`LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`）；其余数据库、Milvus、Neo4j、LightRAG、Rerank 等按功能开启。字段说明见 [环境变量与配置说明.md](环境变量与配置说明.md)。

> 示例中的 `DATABASE_URL` 若指向 MySQL，端口需与**实际**部署一致（本机对接 Compose 时常见为 **13306**）。

### 4.2 前端 `web/.env.local`（可选）

```env
# 代理目标；不填则默认为 http://localhost:8000
VITE_API_BASE_URL=http://localhost:8000
VITE_PORT=5173
```

`vite.config.ts` 将 **`/api`** 与 **`/uploads`** 代理到上述地址，避免开发态跨域。

### 4.3 CORS

开发模式下后端可能对来源较宽松；生产请收紧。若代码中未读取 `CORS_ORIGINS`，以 `gustobot/main.py` 为准。

## 5. 项目结构（开发视角）

```
GustoBot/
├── gustobot/                 # 后端包
│   ├── application/          # Agent、服务、提示词
│   ├── interfaces/http/      # FastAPI 路由（v1、knowledge、lightrag）
│   ├── infrastructure/     # 持久化、知识库、工具
│   ├── config/settings.py    # 环境变量
│   └── main.py               # ASGI 应用入口
├── web/                      # Vue 3 + Vite + TypeScript
├── scripts/                  # run.py、start_chatbot.py、初始化脚本
├── tests/                    # pytest
├── docker-compose.yml
├── Dockerfile
├── requirements.txt
└── .env                      # 本地私密配置（勿提交）
```

更细的模块说明见 [项目架构.md](项目架构.md)。

## 6. 开发工作流

### 6.1 改后端 API

1. 编辑 `gustobot/interfaces/http/` 下路由或 `gustobot/application/` 内逻辑。  
2. 使用 `--reload` 时保存即重启。  
3. 在 **http://localhost:8000/docs** 验证契约。

### 6.2 改 Agent / 路由

- `gustobot/application/agents/lg_builder.py`、`lg_states.py`、`lg_prompts.py`  
- 子图：`kg_sub_graph/...`  
- 路由语义见 [智能体路由速查.md](智能体路由速查.md)

### 6.3 改前端

- 组件：`web/src/components/`（如 `ChatWidget.vue`、`LandingPage.vue`）  
- 使用 **Vue DevTools** 与浏览器 **Network** 面板。  
- 保存后 Vite 热更新。

### 6.4 调试后端

```bash
export DEBUG=true   # Linux/macOS
# Windows: set DEBUG=true

# VS Code / debugpy 示例（按需安装 debugpy）
python -m debugpy --listen 5678 -m uvicorn gustobot.main:application --reload --host 0.0.0.0 --port 8000
```

## 8. 故障排除

| 问题 | 处理 |
|------|------|
| 8000 端口占用 | `netstat -ano \| findstr :8000`（Windows）或 `lsof -i :8000`（Unix） |
| 依赖损坏 | `pip install -r requirements.txt --force-reinstall` |
| 连不上 MySQL/Redis/Neo4j | 确认容器或本机服务已起；主机名在容器内为服务名，宿主机为 `localhost` + 映射端口 |
| 前端拿不到 API | 确认后端 8000 已监听；检查 Vite `proxy` 与 `VITE_API_BASE_URL` |
| `npm install` 失败 | 清缓存、`rm -rf node_modules package-lock.json` 后重装 |
| 热重载异常 | 重启 `npm run dev`；排除文件监听限制（WSL/Docker 挂载） |
