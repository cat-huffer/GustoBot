# 智能体路由速查

本文档汇总主图 **意图路由类型**、**典型问法 → 预期路径**、**子图内工具选择**与 **测试 / 日志** 要点，便于联调与排错。实现以代码为准：`gustobot/application/agents/lg_builder.py`、`lg_states.py`、`kg_sub_graph/.../multi_tool.py`。

更完整的目录说明见：[项目架构.md](项目架构.md)。

---

## 1. 主图：`Router.type` → 下一节点

主图入口：`START → analyze_and_route_query → route_query`（条件边）。

| `Router.type`（`lg_states.Router`） | 下一节点（函数名） | 典型场景 |
|-------------------------------------|-------------------|----------|
| `general-query` | `respond_to_general_query` | 问候、感谢、与菜谱无关的闲聊 |
| `additional-query` | `get_additional_info` | 指代模糊、缺菜名；先过主图侧护栏再追问或拒答 |
| `kb-query` | `create_kb_query` | 典故、文化、营养背景等偏「文本知识」 |
| `graphrag-query` | `create_research_plan` | 做法、食材、图谱关系、技巧推理等 |
| `text2sql-query` | `create_research_plan` | 统计、排名、计数（与 `graphrag-query` 共用节点，Planner 内再选 Text2SQL） |
| `image-query` | `create_image_query` | 文生图、识图 |
| `file-query` | `create_file_query` | 上传文件后的解析 / 入库 / 问答 |

**覆盖路由**：若在调用 `graph` 时，`config["configurable"]` 中带有 `image_path` 或 `file_path`，`route_query` **优先**走向 `create_image_query` 或 `create_file_query`，**不再**采用 LLM 给出的 `Router.type`（见 `lg_builder.route_query`）。

**启发式兜底**（LLM 路由失败或非法 `type` 时）：`_heuristic_router` 按关键词建议 `text2sql-query` 或 `graphrag-query`；仍不合法时可能回退为 `kb-query`。关键词示例（小写匹配）：

- 偏 **Text2SQL**：`统计`、`多少`、`总数`、`数量`、`排名`
- 偏 **GraphRAG**：`怎么做`、`如何做`、`做法`、`步骤`、`火候`、`食材`、`原料`、`需要什么`、`配料`、`用什么`

## 2. 快速查询表（预期行为）

下表为**设计意图与常见表现**；实际 `type` 仍依赖路由 LLM 与兜底逻辑，联调请以日志与 `tests/test_agent_routing.py` 为准。

| 问题示例 | 预期路由 `type` | 主图节点 | 子决策 / 工具倾向 | 数据来源 |
|----------|-----------------|----------|-------------------|----------|
| 你好 / 谢谢 | `general-query` | `respond_to_general_query` | — | 纯 LLM |
| 今天心情不错 | `general-query` | `respond_to_general_query` | — | 纯 LLM |
| 我想做菜 / 这个菜怎么做（未说菜名） | `additional-query` | `get_additional_info` | 护栏 `proceed` → 追问 | LLM |
| 今天天气怎么样 | `additional-query` | `get_additional_info` | 护栏 `end` → 拒答 | — |
| 宫保鸡丁的历史典故 | `kb-query` | `create_kb_query` | KB Router：`postgres` / `milvus` / 组合 + `route: hybrid` 时可能外搜 | pgvector + Milvus 等 |
| 川菜的特点 / 佛跳墙由来 | `kb-query` | `create_kb_query` | 同上 | 向量 + Rerank |
| 西兰花营养价值 | `kb-query` | `create_kb_query` | 常为 `milvus` 或组合 | 向量库 |
| 红烧肉怎么做 | `graphrag-query` | `create_research_plan` | Planner → `predefined_cypher` / `cypher_query` | Neo4j |
| 宫保鸡丁需要哪些食材 | `graphrag-query` | `create_research_plan` | 倾向 `predefined_cypher` 或 `cypher_query` | Neo4j |
| 炒青菜怎么保持翠绿 | `graphrag-query` | `create_research_plan` | 可能 `cypher_query` + `customer_tools` | Neo4j + LightRAG |
| 怎么判断鱼熟了 | `graphrag-query` | `create_research_plan` | 倾向 `customer_tools`（图内为 LightRAG 节点） | LightRAG |
| 什么菜适合感冒吃 | `graphrag-query` | `create_research_plan` | Cypher + `customer_tools` 组合常见 | Neo4j + LightRAG |
| 数据库里有多少道菜 | `text2sql-query` | `create_research_plan` | `tool_selection` → `text2sql_query` | MySQL |
| 哪个菜系菜谱最多 | `text2sql-query` | `create_research_plan` | 同上 | MySQL |
| 麻辣口味的菜有多少道 | `graphrag-query` 或混合 | `create_research_plan` | 可能 `cypher_query` + `text2sql_query` | Neo4j + MySQL |
| 生成红烧肉图片 | `image-query` | `create_image_query` | Prompt 优化 → 文生图 API | 配置见 `settings` |
| 这是什么菜（带图） | `image-query`（或由 `image_path` 强制） | `create_image_query` | Vision → 描述 | 视觉模型 |
| 分析上传菜谱文件 | `file-query`（或由 `file_path` 强制） | `create_file_query` | 读文件 → 入库 / 再查 | 文件 + KB |

**KB 多工具说明**：路由结构化输出里工具名为 **`postgres`** 与 **`milvus`**（对应 PostgreSQL/pgvector 与 Milvus），**不是**文档旧版中的 `pgvector` 字符串。`route` 可为 `local` / `hybrid` 等，用于是否走外搜等策略（见 `multi_tool.py` 中 Router 提示与过滤逻辑）。

**图谱多工具节点名**（与 `tool_selection` 的 `Command` 目标一致）：

| 图内节点名 | 含义 |
|------------|------|
| `predefined_cypher` | 预定义高频 Cypher |
| `cypher_query` | 动态 Text2Cypher → 执行 |
| `customer_tools` | 封装为「客户侧」工具，实现上为 **LightRAG** 查询（`create_graphrag_query_node`） |
| `text2sql_query` | 子图内 Text2SQL → MySQL |

## 3. 各路由类型要点

### 3.1 general-query（闲聊）

- **特点**：不调向量库 / 图数据库；仅用系统提示 + 历史消息调用 LLM。
- **路由 `logic`**：会写入提示，便于模型理解分类原因。

### 3.2 additional-query（补充信息）

- **特点**：`get_additional_info` 内先做强相关的**业务范围护栏**，再决定追问或固定拒答话术。
- **注意**：与 `kg_sub_graph` 里子图的 **Guardrails**（`create_kb_query` / `create_research_plan` 入口）是不同层；主图这一支不跑完整 KB/图谱工作流。

### 3.3 kb-query（向量知识库多工具）

- **流程概要**：`create_kb_query` → KB Multi-tool 子图：护栏 → **KB Router**（选 `postgres` / `milvus`、`route`、`tools`）→ 并行检索 → Rerank（如配置）→ 汇总生成。
- **触发倾向**：典故、文化、流派、营养知识等长文本类问题。

### 3.4 graphrag-query（图谱多工具）

- **流程概要**：`create_research_plan` → Planner 拆任务 → 每任务 `tool_selection` → 上述 `predefined_cypher` / `cypher_query` / `customer_tools` / `text2sql_query` → `summarize` 等聚合 → 最终回答。
- **触发倾向**：做法、步骤、食材、关系查询、技巧推理等。

### 3.5 text2sql-query（结构化问数）

- **特点**：与 `graphrag-query` **共用** `create_research_plan`；是否在子图里走 MySQL 由 `route_type` 与 `tool_selection` 规则（如 `_looks_like_sql_question`）共同决定。
- **触发倾向**：统计、多少、总数、排名等；启发式关键词可抢先给出 `text2sql-query`。

### 3.6 image-query / file-query

- **image**：文生图或视觉理解，依赖 `settings` 中视觉/生图相关配置。
- **file**：解析上传路径指向的文件，与知识导入、再查询等逻辑衔接（具体分支见 `lg_builder` 内 `create_file_query` 实现）。

## 4. 决策流程简图

### 4.1 kb-query（KB 多工具）

```
用户 → create_kb_query → KB Multi-tool 工作流
  → Guardrails（proceed / end）
  → KB Router（postgres / milvus / hybrid…）
  → 检索与 Rerank
  → Finalizer（LLM 成文）
```

### 4.2 graphrag-query / text2sql-query（图谱多工具）

```
用户 → create_research_plan → Multi-tool 工作流
  → Guardrails
  → Planner（tasks）
  → 各 task → tool_selection
       ├ predefined_cypher
       ├ cypher_query（Text2Cypher 链路）
       ├ customer_tools（LightRAG）
       └ text2sql_query
  → summarize / final_answer 等 → 用户可见回复
```

### 4.3 additional-query（主图补充信息）

```
用户 → get_additional_info → 护栏链
  ├ proceed → 追问补充信息
  └ end → 固定拒答话术
```

## 5. 测试命令速查

### 5.1 路由集成脚本（推荐）

项目根目录执行：

```bash
# 完整套件（默认不加参数也会跑套件）
python -m tests.test_agent_routing --suite

# 单条问题（不校验 expected_route，便于探路）
python -m tests.test_agent_routing --single "红烧肉怎么做"
```

依赖真实 LLM 与外部服务时，需配置好环境变量；失败时查看控制台与 `loguru` 输出。

### 5.2 Pytest 说明

`tests/test_agent_routing.py` 在**未**设置 `GUSTOBOT_RUN_INTEGRATION_TESTS=1` 时会被 `pytest` **整模块跳过**（避免默认 CI 打外部接口）。需要纳入 pytest 时：

```bash
set GUSTOBOT_RUN_INTEGRATION_TESTS=1
pytest tests/test_agent_routing.py -v
```

（Linux/macOS 使用 `export GUSTOBOT_RUN_INTEGRATION_TESTS=1`。）

### 5.3 HTTP 调用示例

非流式（路径以实际部署为准，常见为 `/api/v1/chat/`，`v1` 下 `chat` 路由的 `POST /`）：

```bash
curl -X POST "http://localhost:8000/api/v1/chat/" ^
  -H "Content-Type: application/json" ^
  -d "{\"message\": \"红烧肉怎么做\", \"session_id\": \"test_001\"}"
```

带图片（`image_path` 会强制图片分支）：

```bash
curl -X POST "http://localhost:8000/api/v1/chat/" ^
  -H "Content-Type: application/json" ^
  -d "{\"message\": \"这是什么菜\", \"image_path\": \"/uploads/xxx.jpg\", \"session_id\": \"test_002\"}"
```

带文件：

```bash
curl -X POST "http://localhost:8000/api/v1/chat/" ^
  -H "Content-Type: application/json" ^
  -d "{\"message\": \"分析这个菜谱\", \"file_path\": \"/uploads/xxx.txt\", \"session_id\": \"test_003\"}"
```

Windows PowerShell 可把 `^` 换为 `` ` `` 或写成单行 JSON。

## 6. 性能与日志（量级参考）

| 路由类型 | 量级（视模型与数据规模变化大） | 主要耗时 |
|----------|--------------------------------|----------|
| general-query | 通常较快 | LLM |
| additional-query | 中等 | 护栏 + LLM |
| kb-query | 中等偏慢 | 向量检索 + Rerank |
| graphrag-query | 偏慢 | Cypher 生成/执行、多工具并行 |
| customer_tools（LightRAG） | 往往更慢 | 图检索与推理 |
| text2sql-query | 中等 | SQL 生成 + MySQL |
| image-query | 视模式 | Vision 或生图 API |
| file-query | 中等 | 读文件与入库 |

**日志关键字（示例）**

- 路由：`Analyze user query type`、`Analyze user query type completed`
- KB：`kb-multi-tool` / `KB router decision`
- 图谱：Planner、`tool_selection`、Cypher/SQL 生成日志（具体文案以代码中的 `logger` 为准）
- 降级：`Router LLM failed`、`Falling back to KB query`、KB 工作流不可用时的 fallback

## 7. 快速验证清单

- [ ] 纯寒暄 → `general-query`，无检索日志
- [ ] 模糊指代 → `additional-query`，护栏 `proceed` 或 `end`
- [ ] 典故文化 → `kb-query`，出现 `postgres`/`milvus` 检索
- [ ] 明确菜谱做法 → `graphrag-query`，可能出现 `predefined_cypher` 或 `cypher_query`
- [ ] 技巧/判断类 → 可能出现 `customer_tools`（LightRAG）
- [ ] 统计类 → `text2sql-query` 或子图内 `text2sql_query`
- [ ] 越界问题 → `additional-query` + 护栏拒答
- [ ] LLM 异常 → 启发式或 `kb-query` 兜底，服务不崩溃
