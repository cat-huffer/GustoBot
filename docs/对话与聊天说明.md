# 对话与聊天说明

本文面向**使用与对接聊天能力**的读者：说明 GustoBot 如何通过统一聊天 API 接入 **LangGraph 多智能体**、会话持久化、流式输出及前端入口。实现代码主要在 `gustobot/interfaces/http/v1/chat.py`、`gustobot/application/agents/lg_builder.py`。

更细的**路由类型与工具选择**见 [智能体路由速查.md](智能体路由速查.md)；环境与服务启动见 [快速开始.md](快速开始.md)、[部署指南.md](部署指南.md)。

---

## 1. 能力概览

- **统一入口**：一条 HTTP 请求即可完成意图路由、多工具子图、再返回自然语言答案（及可选 `sources`）。
- **会话**：`session_id` 与数据库中的会话、消息关联；未传则由服务端新建。
- **多模态参数**：`image_path`、`file_path` 传入后，主图条件边会**优先**走图片/文件分支（见 `lg_builder.route_query`）。
- **流式**：SSE 推送分片，适合 Web 端打字机效果。
- **前端**：仓库 `web/`（Vue + Vite），默认开发端口多为 **5173**；与后端 **8000** 分离。

## 2. 快速启动（摘要）

```bash
cp .env.example .env   # 配置 LLM_API_KEY 等
python scripts/start_chatbot.py
```

或仅后端：`python -m uvicorn gustobot.main:application --reload --host 0.0.0.0 --port 8000`

访问：

- 前端（若已 `npm run dev`）：http://localhost:5173/
- OpenAPI：http://localhost:8000/docs

## 3. 路由类型（`Router.type`）

与主图 `analyze_and_route_query` 输出一致（示例问法仅供参考，实际以模型与启发式为准）：

| `type` | 说明 | 示例问法 |
|--------|------|----------|
| `general-query` | 闲聊、问候 | 「你好」「谢谢」 |
| `kb-query` | 向量知识库 / 典故文化 | 「佛跳墙的由来」 |
| `graphrag-query` | 图谱与多工具（含 LightRAG 等） | 「红烧肉怎么做」「需要哪些食材」 |
| `text2sql-query` | 结构化统计（与图谱分支共用节点） | 「数据库里有多少道菜」 |
| `additional-query` | 信息不足或需追问/拒答 | 「我想做菜」 |
| `image-query` | 生图或识图 | 「生成一道麻婆豆腐的图片」 |
| `file-query` | 结合上传文件 | 「分析这个菜谱」+ `file_path` |

**注意**：若在请求里带上 **`image_path` 或 `file_path`**（且 `configurable` 传入图），会**覆盖**文本路由结果，强制进入图片或文件处理分支。

## 4. 聊天 API（前缀 `/api/v1/chat`）

`chat` 路由在 `v1` 下以 **`/chat`** 为前缀，故完整路径形如 **`/api/v1/chat/...`**（`API_V1_PREFIX` 默认为 `/api/v1`）。

### 4.1 请求体 `ChatRequest` 主要字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `message` | string | 用户消息（必填） |
| `session_id` | string，可选 | 多轮会话 ID；不传则新建 |
| `user_id` | string，可选 | 默认 `default_user`，用于会话归属 |
| `stream` | bool | 仅用于兼容模型；**流式请调专用 SSE 路由** |
| `image_path` | string，可选 | 已上传图片路径（如 `/uploads/xxx.jpg`） |
| `file_path` | string，可选 | 已上传文件路径 |
| `ingest_incremental` | bool，可选 | Excel 等导入是否增量；默认跟 `settings.INGEST_INCREMENTAL_DEFAULT` |

### 4.2 非流式（推荐）

**`POST /api/v1/chat/`**

- 写入用户消息 → `graph.ainvoke`（`thread_id` 使用 `session_id`）→ 写入助手消息。
- 响应 `ChatResponse`：`message`、`session_id`、`message_id`、`route`、`route_logic`、`sources`、`metadata` 等。

示例：

```bash
curl -s -X POST "http://localhost:8000/api/v1/chat/" ^
  -H "Content-Type: application/json" ^
  -d "{\"message\": \"红烧肉怎么做？\", \"session_id\": \"demo-1\", \"stream\": false}"
```

### 4.3 流式（SSE）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | **`/api/v1/chat/stream`** | 推荐；JSON body 同 `ChatRequest` |
| POST | `/api/v1/chat/chat/stream` | 旧版别名，等价 |
| GET | `/api/v1/chat/chat/stream` | 旧版兼容；参数用 Query：`message`、`session_id`、`user_id`、`image_path`、`file_path` 等 |

响应为 **`text/event-stream`**，数据行为 JSON 字符串的 SSE `data:` 分片（含 `metadata`、`message` 类型等，见 `ChatStreamChunk`）。

**实现说明**：当前流式路径在代码注释中标明 **助手完整回复可能未写入数据库**（与非流式路径行为不一致）；若需严格落库，请以 `chat.py` 最新实现为准或优先使用非流式接口。

### 4.4 旧版别名

**`POST /api/v1/chat/chat`** 与 **`POST /api/v1/chat/`** 行为相同，建议在文档与新代码中统一使用 **`/api/v1/chat/`**。

## 5. 会话 API（前缀 `/api/v1/sessions`）

匿名会话管理，无登录态（见 `sessions.py`）：

- **`GET /api/v1/sessions/`** — 列表，支持 `user_id`、`skip`、`limit`、`active_only`
- **`POST /api/v1/sessions/`** — 创建会话
- 另有按 ID 查询、更新、删除等（以 OpenAPI 为准）

聊天接口也会在首次请求时**自动创建会话**（若未传已有 `session_id`）。

### 5.1 历史与清空

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/chat/history/{session_id}` | 分页参数 `limit`、`offset` |
| DELETE | `/api/v1/chat/session/{session_id}` | 清空该会话下消息（非删除会话实体） |

### 5.2 路由说明（调试）

**`GET /api/v1/chat/routes`** — 返回各 `route` 的说明与示例，便于前端展示。

---

## 6. 文件与图片上传

聊天里的 `file_path` / `image_path` 需指向服务端可访问路径。上传接口在 **`/api/v1/upload`** 下，例如：

- **`POST /api/v1/upload/file`** — 文档类（扩展名见 `upload.py` 中 `ALLOWED_FILE_TYPES`）
- 另有图片上传路由（见 `upload.py` 与 `/docs`）

上传响应中的路径填入后续 **`ChatRequest`** 即可。

---

## 7. 数据流（简图）

```
客户端
  → POST /api/v1/chat/ 或 /stream
  → chat.py（会话、持久化用户消息）
  → lg_builder.graph.ainvoke（configurable: thread_id=session_id, image_path, file_path）
  → 主图路由 → 各分支子图 / 工具
  → 助手回复（+ route / sources）
  → 非流式：写入助手消息并返回 JSON
```

持久化使用 `gustobot/infrastructure/persistence`；写入消息时会避免把过大 **`agent_state`** 塞进元数据（见 `save_message`）。

## 10. 注意事项

1. **密钥**：配置 `LLM_API_KEY`（及 `settings` 中兼容的 `OPENAI_*` 别名）。  
2. **依赖服务**：图谱、向量库、MySQL 等未启动时，对应分支会失败或降级，需看日志。  
3. **上传与磁盘**：注意 `FILE_UPLOAD_MAX_MB` 与反向代理 body 限制。  
4. **会话 ID**：前端可将 `session_id` 存 **localStorage** 以实现多轮连续对话。
