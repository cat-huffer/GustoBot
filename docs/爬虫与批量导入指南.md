# 爬虫与批量导入指南

本文说明如何通过 **Wikipedia 公开 API** 与 **本地 JSON** 两种方式，向 GustoBot 的「菜谱型」知识库批量写入数据。写入均走后端 HTTP 接口 **`POST /api/v1/knowledge/recipes/batch`**，需先启动可访问的后端（本地或远程）。

实现代码位置：

- 爬虫 CLI：`gustobot/crawler/cli.py`
- Wikipedia 抓取与映射：`gustobot/crawler/wikipedia.py`
- JSON 字段规范化：`gustobot/infrastructure/knowledge/recipe_import.py`
- 批量导入脚本：`scripts/import_recipes.py`

更多启动与部署见：[快速开始.md](快速开始.md)、[部署指南.md](部署指南.md)。

---

## 1. 前置条件

1. **后端已启动**，且能访问 OpenAPI 文档，例如：

   ```bash
   curl -s -o NUL -w "%{http_code}" http://localhost:8000/docs
   ```

   若返回 `200` 表示服务可达（Linux/macOS 可将 `NUL` 改为 `/dev/null`）。

2. **网络**：Wikipedia 方式需能访问 `https://{lang}.wikipedia.org`（默认 `zh`）。

3. **路径**：以下命令均在**仓库根目录**执行；确保已安装项目依赖并激活虚拟环境。

> 文档中若写 `docker-compose up -d`，请以你仓库内实际的 Compose 文件名为准；核心是 **API 基址正确**（默认 `http://localhost:8000`）。

---

## 2. 知识库 API 与数据形态

- **批量写入端点**：`{api_base_url}/api/v1/knowledge/recipes/batch`
- **请求体**：菜谱对象数组，常见字段包括 `name`、`category`、`difficulty`、`time`、`ingredients`、`steps`、`tips`、`nutrition` 等（以后端 `knowledge_router` 与向量入库逻辑为准）。

**Wikipedia 导入的映射策略**（`wikipedia_page_to_recipe`）：

- `name`：页面标题  
- `category`：`Wikipedia` 或 `Wikipedia/{query}`  
- `steps`：摘要正文 `extract` 作为**单条步骤**，便于向量检索验证（并非真实烹饪步骤结构）  
- `tips`：附页面 URL（`来源：…`）  
- `ingredients`：一般为 `null`

**本地 JSON 导入** 经 `recipe_json_entry_to_recipe` 等函数，将中文菜谱字段（如 `主食材`、`辅料`、`做法`）转为上述 API 字段。

## 3. 方式一：Wikipedia 爬虫（`gustobot.crawler.cli`）

### 3.1 工作原理简述

1. 调用 MediaWiki API：`list=search` 按关键词取标题列表（单次最多 50 条，受 `--limit` 约束）。  
2. 再批量请求 `prop=extracts|info`，取**仅导语**的纯文本摘要与规范 URL。  
3. 若指定 `--import-kb`，将转换后的 JSON **POST** 到 `/api/v1/knowledge/recipes/batch`。

### 3.2 命令行参数一览

| 参数 | 说明 |
|------|------|
| `--query` | 必填，搜索关键词（如 `川菜`） |
| `--limit` | 抓取条数，默认 `10`，与 API 上限共同约束 |
| `--lang` | 语言子域，默认 `zh`（即 `zh.wikipedia.org`） |
| `--import-kb` | 写入知识库；**不加**则只打印或配合 `--output` 落盘 |
| `--api-base-url` | 后端根 URL，默认 `http://localhost:8000` |
| `--timeout` | HTTP 超时（秒），默认 `30` |
| `--output path.json` | 将原始抓取结果写入 JSON 文件 |
| `--dry-run` | 不 POST；打印转换后的菜谱 JSON（与「未加 `--import-kb`」时行为一致，均为只输出） |

### 3.3 示例

**仅预览（不写入 KB）**

```bash
python -m gustobot.crawler.cli wikipedia --query "川菜" --limit 5 --dry-run
```

**抓取并写入 KB**

```bash
python -m gustobot.crawler.cli wikipedia --query "川菜" --import-kb --limit 10
```

**指定后端地址**

```bash
python -m gustobot.crawler.cli wikipedia --query "川菜" --import-kb --limit 10 --api-base-url "http://127.0.0.1:8000"
```

**导出原始页数据到文件**

```bash
python -m gustobot.crawler.cli wikipedia --query "宫保鸡丁" --limit 3 --output data/wiki_pages.json
```

### 3.4 使用注意

- 摘要长度与内容受 Wikipedia 策略与条目质量影响，**适合打通检索链路**，不适合作为权威菜谱数据。  
- 频繁、大批量请求请遵守 [Wikipedia 机器人礼仪](https://zh.wikipedia.org/wiki/Wikipedia:%E6%9C%BA%E5%99%A8%E4%BA%BA) 与站点速率限制；调试时优先 **小 `--limit`**。  
- CLI 使用 `httpx` 且 `trust_env=False`，**默认不走系统代理**；若必须在代理环境下访问外网，需改代码或在本机直连。

## 4. 方式二：从 JSON 批量导入（`scripts/import_recipes.py`）

### 4.1 支持的 JSON 根结构

1. **以菜名为 key 的 dict**（与仓库内 `data/recipe.json` 一致）：每个 value 为一条菜谱子对象。  
2. **数组 list**：每项为 dict；需能解析出名称字段 `name` / `title` / `菜名`。  
   - 若含 `主食材`、`辅料`、`做法` 等，会走与 `recipe.json` 相同的映射。  
   - 否则在已接近 API 形态时，会做轻量字段对齐（`category`/`类型`、`time`/`耗时` 等）。

映射细节见 `gustobot/infrastructure/knowledge/recipe_import.py` 中 `recipe_json_entry_to_recipe` 与 `split_steps` 等。

### 4.2 命令行参数一览

| 参数 | 说明 |
|------|------|
| `--file` | 必填，JSON 文件路径 |
| `--batch-size` | 每请求条数，默认 `100` |
| `--api-base-url` | 后端根 URL，默认 `http://localhost:8000` |
| `--limit N` | 仅处理前 N 条（用于试跑） |
| `--dry-run` | 不 POST；只打印**最多** `min(batch_size, 5)` 条转换样例 JSON |
| `--timeout` | HTTP 超时（秒），默认 `60` |

### 4.3 示例

**转换预览（不写入）**

```bash
python scripts/import_recipes.py --file data/recipe.json --batch-size 100 --dry-run
```

**小批量写入验证**

```bash
python scripts/import_recipes.py --file data/recipe.json --batch-size 100 --limit 200
```

**全量写入（耗时可较长）**

```bash
python scripts/import_recipes.py --file data/recipe.json --batch-size 100
```

**指定后端**

```bash
python scripts/import_recipes.py --file data/recipe.json --batch-size 100 --api-base-url "http://localhost:8000"
```

导入过程中会按批打印 `sent` / `inserted` / `rate`；完成后输出总导入条数。

多行命令在 PowerShell 中可用反引号 `` ` `` 续行，或写成一行。例如：

```powershell
python -m gustobot.crawler.cli wikipedia --query "川菜" --import-kb --limit 10 --api-base-url "http://localhost:8000"
```

## 6. 常见问题

| 现象 | 排查建议 |
|------|----------|
| 无法连接 `localhost:8000` | 确认进程已监听端口；防火墙；`--api-base-url` 是否含错误路径（只需根 URL，不要带 `/docs`）。 |
| Wikipedia 请求失败 | 检查外网、DNS、`--lang` 是否正确；缩小 `--limit` 重试。 |
| POST 返回 4xx/5xx | 看响应体与后端日志；批量写入会触发向量入库，注意 Milvus/embedding 等配置（见 [环境变量与配置说明.md](环境变量与配置说明.md)）。 |
| 导入成功但检索不到 | 确认向量库集合与后端使用的 collection 一致；必要时查看 `knowledge_router` 相关日志与初始化脚本。 |
| `--dry-run` 与预期条数不一致（JSON 脚本） | 设计如此：`import_recipes.py` 的 dry-run **仅展示少量样例**，不是全量转换输出。 |
