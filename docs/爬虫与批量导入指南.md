# 爬虫与批量导入指南（初学者友好版）

## 本文适合谁？

- 你已经能**启动 GustoBot 后端**（或至少知道「有一个在跑的 Web 服务」），想**往知识库里批量加菜谱数据**。
- 你对 **Python 命令行**、**JSON 文件** 有基本概念即可；不要求写过爬虫。

**读完本文你能做到：**

1. 理解数据是**怎么从脚本 → HTTP 接口 → 后端 → 向量库**这条链路进去的。  
2. 会用两种方式往库里灌数据：**Wikipedia 摘要（演示/联调用）**、**本地 JSON（正式菜谱结构）**。  
3. 遇到连接失败、导入成功但搜不到等问题时，知道**先查哪几步**。

---

## 1. 先搞懂几个词（术语速查）

| 术语 | 通俗理解 |
|------|----------|
| **API** | 后端提供的「网址 + 约定好的数据格式」。脚本用 HTTP **POST** 把菜谱 JSON 发给后端，就像填表提交。 |
| **API 基址（base URL）** | 服务的根地址，例如 `http://localhost:8000`。批量接口的完整地址是：**基址 + `/api/v1/knowledge/recipes/batch`**。 |
| **批量导入** | 一次请求里带**多条**菜谱对象（数组），减少「一条菜发一次请求」的开销。 |
| **向量 / 向量库（如 Milvus）** | 后端会把文本变成向量存起来，聊天时才能「按意思搜菜谱」。导入成功通常意味着**已向量化并写入**；若 Embedding/Milvus 未配置好，接口可能报错或行为异常。 |
| **MediaWiki / Wikipedia API** | 维基百科开放的数据接口。本项目的 Wikipedia 爬虫**只取公开摘要**，不登录、不抓整站 HTML。 |
| **`--dry-run`** | **排练**：只在你电脑上转换/打印数据，**不**发给后端，适合先检查格式对不对。 |

---

## 2. 整体流程（建议对着图想一遍）

```text
┌─────────────────┐     POST JSON 数组      ┌──────────────────┐
│  你的脚本/CLI    │ ────────────────────►  │  GustoBot 后端    │
│  (本机终端运行)  │   /api/v1/knowledge/   │  knowledge_router │
└─────────────────┘     recipes/batch      └────────┬─────────┘
        │                                            │
        │  ① Wikipedia：联网搜摘要再映射              │  校验、调用知识服务
        │  ② JSON：读本地文件再映射                     ▼
        │                                     向量库（如 Milvus）等
```

**你需要记住的一点：**  
脚本运行在**你的电脑**上，后端运行在 **localhost 或 Docker 里**。`--api-base-url` 必须指向**后端真实监听的地址**，否则 POST 会连不上。

---

## 3. 前置条件（按顺序自检）

### 3.1 环境与目录

1. **在仓库根目录**打开终端（能看到 `gustobot/`、`scripts/`、`data/` 那一层）。  
2. 已安装依赖并（建议）使用虚拟环境，例如：

   ```bash
   pip install -e .
   ```

   具体以 [开发指南.md](开发指南.md)、[快速开始.md](快速开始.md) 为准。

### 3.2 后端必须已启动

在浏览器打开 **`http://localhost:8000/docs`** 能看到 Swagger 页面，或用命令探测（**Windows PowerShell**）：

```powershell
Invoke-WebRequest -Uri "http://localhost:8000/docs" -Method Head -UseBasicParsing | Select-Object StatusCode
```

若状态码为 `200`，说明服务可达。

> 使用 Docker 时，端口可能是映射后的地址，请与 [部署指南.md](部署指南.md) 一致；**不要把 `/docs` 写进 `--api-base-url`**，基址只要到端口即可，例如 `http://localhost:8000`。

### 3.3 网络（仅 Wikipedia 方式）

- 需能访问 `https://{lang}.wikipedia.org`（默认中文 `zh`）。  
- 本项目 CLI 使用 `httpx` 且 **`trust_env=False`**，默认**不走系统代理**；若你必须走代理，需要改代码或换网络环境。

### 3.4 向量与 Embedding（导入成功的前提）

批量写入会触发**向量化**。若 Milvus、Embedding 相关环境变量未配置或服务未起，可能出现 **5xx** 或导入后检索异常。请先对照 [环境变量与配置说明.md](环境变量与配置说明.md) 与 [快速开始.md](快速开始.md)。

## 4. 知识库接口与数据长什么样？

- **端点**：`POST {api_base_url}/api/v1/knowledge/recipes/batch`  
- **请求体**：**JSON 数组**，每个元素是一条「菜谱」对象。常见字段包括：`name`、`category`、`difficulty`、`time`、`ingredients`、`steps`、`tips`、`nutrition` 等（**以后端 `knowledge_router` 与知识服务实现为准**）。

实现与路由可参考：`gustobot/interfaces/http/knowledge_router.py`。

---

## 5. 两种方式对比（该选哪个？）

| 对比项 | Wikipedia 爬虫 | 本地 JSON 批量脚本 |
|--------|----------------|---------------------|
| **典型用途** | 快速验证「检索链路是否通」、演示 | 导入真实/整理好的菜谱数据 |
| **数据质量** | 维基**摘要**，不是标准烹饪步骤结构 | 取决于你的 JSON；支持仓库同款中文字段 |
| **依赖** | 外网 + Wikipedia | 仅需后端与本地文件 |
| **命令入口** | `python -m gustobot.crawler.cli wikipedia ...` | `python scripts/import_recipes.py ...` |

## 6. 方式一：Wikipedia 爬虫（`gustobot.crawler.cli`）

### 6.1 实现位置（想读代码时）

- CLI：`gustobot/crawler/cli.py`  
- 抓取与映射：`gustobot/crawler/wikipedia.py`

### 6.2 工作原理（初学者版）

1. 用关键词调用 MediaWiki **`list=search`**，拿到一批页面标题（单次最多约 50 条，实际条数还受 `--limit` 限制）。  
2. 再请求 **`prop=extracts|info`**，取**导语级纯文本**和规范 URL。  
3. 映射函数 `wikipedia_page_to_recipe` 把页面变成菜谱形状 JSON：  
   - `name`：页面标题  
   - `category`：`Wikipedia` 或 `Wikipedia/{query}`  
   - `steps`：摘要 `extract` 当作**一条「步骤」**（仅为打通检索，不是真实步骤列表）  
   - `tips`：附页面 URL（`来源：…`）  
   - `ingredients`：一般为 `null`  
4. 若加 `--import-kb`，则 **POST** 到 `/api/v1/knowledge/recipes/batch`。

### 6.3 命令行参数

| 参数 | 说明 |
|------|------|
| `--query` | **必填**，搜索关键词（如 `川菜`） |
| `--limit` | 抓取条数，默认 `10` |
| `--lang` | 语言子域，默认 `zh`（即 `zh.wikipedia.org`） |
| `--import-kb` | 写入知识库；**不加**则只打印 JSON（或配合 `--output` 写文件） |
| `--api-base-url` | 后端根 URL，默认 `http://localhost:8000` |
| `--timeout` | HTTP 超时（秒），默认 `30` |
| `--output path.json` | 将**原始抓取页**数据写入 JSON |
| `--dry-run` | 不 POST；打印转换后的菜谱 JSON（与未加 `--import-kb` 时类似，均为只输出） |

### 6.4 示例命令

**先预览，不写入（推荐第一次就这样试）**

```bash
python -m gustobot.crawler.cli wikipedia --query "川菜" --limit 5 --dry-run
```

**抓取并写入知识库**

```bash
python -m gustobot.crawler.cli wikipedia --query "川菜" --import-kb --limit 10
```

**后端不在本机默认端口时**

```bash
python -m gustobot.crawler.cli wikipedia --query "川菜" --import-kb --limit 10 --api-base-url "http://127.0.0.1:8000"
```

**把原始页数据存盘（便于你打开 JSON 学习结构）**

```bash
python -m gustobot.crawler.cli wikipedia --query "宫保鸡丁" --limit 3 --output data/wiki_pages.json
```

### 6.5 使用注意与礼仪

- 维基摘要**适合联调检索**，不要当作权威菜谱。  
- 遵守 [Wikipedia 机器人礼仪](https://zh.wikipedia.org/wiki/Wikipedia:%E6%9C%BA%E5%99%A8%E4%BA%BA)；调试时 **`--limit` 开小一点**。  
- 本项目 CLI **默认不走代理**（见上文 3.3）。

## 7. 方式二：从 JSON 批量导入（`scripts/import_recipes.py`）

### 7.1 实现位置

- 脚本：`scripts/import_recipes.py`  
- 字段规范化：`gustobot/infrastructure/knowledge/recipe_import.py`（`recipe_json_entry_to_recipe`、`split_steps` 等）

### 7.2 支持的 JSON「最外层」结构

1. **对象（dict）**：键为菜名，值为一条菜谱子对象——与仓库内 `data/recipe.json` 风格一致。  
2. **数组（list）**：每项为一个 dict。需能解析出名称：`name` / `title` / `菜名`。  
   - 若含 **`主食材`、`辅料`、`做法`** 等中文键，会走与 `recipe.json` 相同的映射。  
   - 否则在已接近 API 形态时，会做轻量字段对齐（如 `category`/`类型`、`time`/`耗时`）。

### 7.3 中文菜谱 JSON 最小示例（便于你对照）

下面是一条「单菜」在 **dict 根结构**里可能出现的形态（键为菜名）：

```json
{
  "番茄炒蛋": {
    "类型": "家常菜",
    "耗时": "15分钟",
    "主食材": [["番茄", "2个"], ["鸡蛋", "3个"]],
    "辅料": [["盐", "少许"]],
    "做法": "1：番茄切块。2：鸡蛋打散炒熟盛出。3：炒番茄出汁后合炒调味。",
    "口味": "咸鲜",
    "工艺": "炒"
  }
}
```

映射结果里：`主食材`+`辅料` 会合并进 `ingredients`；`做法` 会按序号/换行/句号等规则拆成 `steps`；`口味`、`工艺` 会进 `tips`。**具体规则以 `recipe_import.py` 为准。**

### 7.4 命令行参数

| 参数 | 说明 |
|------|------|
| `--file` | **必填**，JSON 文件路径 |
| `--batch-size` | 每请求条数，默认 `100` |
| `--api-base-url` | 后端根 URL，默认 `http://localhost:8000` |
| `--limit N` | 只处理前 N 条（试跑很有用） |
| `--dry-run` | 不 POST；只打印**最多** `min(batch_size, 5)` 条转换样例（**不是全量预览**，属刻意设计） |
| `--timeout` | HTTP 超时（秒），默认 `60` |

### 7.5 示例命令（建议按此顺序练）

**① 先看转换结果（不写入）**

```bash
python scripts/import_recipes.py --file data/recipe.json --batch-size 100 --dry-run
```

**② 小批量真写入（例如前 200 条）**

```bash
python scripts/import_recipes.py --file data/recipe.json --batch-size 100 --limit 200
```

**③ 全量导入（耗时可较长）**

```bash
python scripts/import_recipes.py --file data/recipe.json --batch-size 100
```

运行时会按批打印 `sent` / `inserted` / `rate`；结束会输出总导入条数。

## 8. Windows / PowerShell 提示

- 整条命令可写在一行，避免换行转义问题。  
- 需要续行时可用反引号 `` ` ``（PowerShell）：

```powershell
python -m gustobot.crawler.cli wikipedia `
  --query "川菜" --import-kb --limit 10 `
  --api-base-url "http://localhost:8000"
```

路径含空格时给 `--file` 加引号，例如 `--file "D:\data\recipe.json"`。

## 9. 常见问题（FAQ）

| 现象 | 可能原因 | 建议 |
|------|----------|------|
| 连不上 `localhost:8000` | 后端没起、端口错了、防火墙 | 先打开 `/docs`；`--api-base-url` 只写到端口，不要带 `/docs` |
| Wikipedia 报错 | 网络/DNS/被墙、`--lang` 写错 | 换网络、缩小 `--limit`、试 `--lang en` 对比 |
| POST 返回 **4xx** | 请求体格式、鉴权（若将来加了） | 看响应 JSON 与后端日志 |
| POST 返回 **5xx** | 向量库、Embedding、内部异常 | 查 [环境变量与配置说明.md](环境变量与配置说明.md)，确认 Milvus 与 Embedding 可用 |
| 导入成功但聊天搜不到 | collection 不一致、缓存、搜的是别的库 | 对照后端使用的 Milvus collection 与导入日志；重启相关服务后再试 |
| `--dry-run` 只显示几条（JSON 脚本） | **正常** | `import_recipes.py` 的 dry-run 最多展示 `min(batch_size, 5)` 条样例 |
| `python -m gustobot.crawler.cli` 报模块找不到 | 不在仓库根、未安装包 | `cd` 到项目根；`pip install -e .` |

## 10. 给初学者的学习顺序建议

1. 启动后端，打开 `/docs`，在文档里找到 **`POST /recipes/batch`**，看一眼请求体长什么样。  
2. 跑 **Wikipedia + `--dry-run`**，理解「外部数据 → 映射 → JSON」。  
3. 打开 `data/recipe.json`（若存在）或自己写一小段 **7.3 节** 那样的 JSON，跑 **`import_recipes.py --dry-run`**。  
4. **`--limit 5`** 小批量真导入，再在对话里用相关问题检索验证。  
5. 需要改字段规则时，再读 `recipe_import.py` 与 `knowledge_router.py`。
